# HTRAM Release v2.3.1

## Огляд релізу (Release Overview)
Реліз `v2.3.1` впроваджує повну відповідність клієнта тривог правилам та рекомендаціям публічного сервера [JAAM Server API](https://info.jaam.net.ua/fusion/api/server-api/), додає окремі звукові сигнали при зміні рівня загрози (ескалація Жовтий → Червоний та деескалація Червоний → Жовтий), усуває перезавантаження через брак пам'яті при завантаженні графічних асетів через HTTP та уніфікує версію прошивки в єдиному джерелі (`esphome/htram-core.yaml`).

---

## Основні зміни (Key Features & Improvements)

### 1. Повна відповідність вимогам JAAM Server API (`jaam_ws`)
- **Ідентифікація клієнта при підключенні**: Одразу після відкриття WebSocket-сесії до `ws://ws.jaam.net.ua:80/data_fusion_v1` клієнт передає стабільний апаратний ідентифікатор `chip_id:<MAC>` (12 hex-символів у верхньому регістрі без роздільників) та актуальну версію ПЗ `firmware:<version>`.
- **Ping / Pong та контроль тиші**: Частоту клієнтських ping-кадрів встановлено на `45 с` (із автоматичною відповіддю PONG на серверні ping-кадри кожні `20 с`). Якщо протягом `90 с` (`DEAD_LINK_MS`) по з'єднанню немає жодних кадрів, ініціюється контрольоване перепідключення.
- **Експоненційний Backoff із Jitter ±20%**: Реалізовано шкалу затримок `5 с → 10 с → 20 с → 40 с → 80 с → 160 с → 300 с` із випадковим розкидом `0.8x..1.2x`. Базова затримка скидається до `5 с` лише якщо з'єднання стабільно пропрацювало `>= 60 с`. При закритті з кодом `1008` (Policy Violation) або HTTP-помилці рукостискання (`>= 400`) клієнт одразу переходить до максимальної паузи (`300 с`). За відсутності Wi-Fi спроби підключення призупиняються.
- **Контроль хеш-ланцюжка `0xA1` та TTL для `0xA2`**: Додано валідацію довжини бінарних записів, безпечне ігнорування невідомих типів пакетів, перевірку неперервності `hash_previous == last_hash_` у дифах `0xA1` (із перепідключенням при розриві синхронізації) та автоматичне очищення одноразових сповіщень `0xA2` після спливання `NOTIF_TTL_MS` (3 хвилини).
- **Атрибуція**: У веб-інтерфейсі пристрою та документації додано явну згадку й посилання на проєкт [JAAM (jaam.net.ua)](https://jaam.net.ua).

### 2. Звукова індикація ескалації та деескалації рівня тривоги
- При переході тривоги з **Жовтого** рівня (дрони / підвищена увага) на **Червоний** (ракетна небезпека) відтворюється окремий тривожний висхідний сигнал (`alert_escalate_rtttl`).
- При переході з **Червоного** рівня назад на **Жовтий** відтворюється інформативний низхідний сигнал (`alert_deescalate_rtttl`).

### 3. Потокова буферизація при завантаженні графічних асетів (`Gd32AssetsHandler`)
- Замінено попереднє резервування суцільного буфера у купі на покрокову буферизацію чанками по 4 КБ у `Gd32AssetsHandler`, що усуває ризик OOM-перезавантаження ESP32 під час OTA-оновлення іконок SPI Flash.

### 4. Підвищення версій компонентів та уніфікація
- **ESPHome Firmware**: `v2.3.1` (визначається в єдиному місці — `esphome/htram-core.yaml`, автоматично підхоплюється всіма конфігураціями та макросом `ESPHOME_PROJECT_VERSION`)
- **GD32 Coprocessor Firmware**: `v1.3.3` (`0x0133`, без змін)
- **Graphic Assets Container**: 47 активних асетів (без змін)
