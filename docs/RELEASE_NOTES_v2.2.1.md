# HTRAM Release v2.2.1

## Огляд релізу (Release Overview)
Реліз `v2.2.1` виправляє критичну проблему надійності та довготривалої стабільності підключення до хмарного сервісу повітряних тривог JAAM Fusion WebSocket (`ws.jaam.net.ua`), через яку пристрої могли втрачати з'єднання після тривалої роботи й пропускати тривоги. Також додано моніторинг статусу з'єднання у REST API, веб-інтерфейс та утиліти діагностики.

---

## Основні зміни (Key Features & Improvements)

### 1. Автоматичне перепідключення WebSocket при закритті сервером (Auto-Reconnect on Close)
- **Проблема**: Публічний WebSocket-сервер JAAM працює через зворотний проксі Cloudflare, який періодично закриває або оновлює тривалі TCP/WS-сесії за допомогою штатного кадру WebSocket Close (opcode `0x08`). У бібліотеці `esp_websocket_client` прапорець `enable_close_reconnect` за замовчуванням вимкнено (`false`), через що фоновий процес FreeRTOS `websocket_task` завершував свою роботу (`vTaskDelete`) і клієнт більше ніколи не намагався перепідключитися аж до ручного перезавантаження девайса.
- **Виправлення**: 
  - Активовано `cfg.enable_close_reconnect = true;` у конфігурації WebSocket клієнта.
  - Обробник подій `ws_event_handler` тепер коректно реагує на події `WEBSOCKET_EVENT_ERROR`, скидаючи статус підключення та дозволяючи автоматичному циклу reconnect відновити сесію.

### 2. Сторожовий таймер та супервізор з'єднання в головному циклі (Supervisory Watchdog)
- У компоненті `JaamWsComponent::loop()` впроваджено активний нагляд за працездатністю клієнта:
  - Регулярна перевірка активності Wi-Fi та реального стану сокета через `esp_websocket_client_is_connected`.
  - Якщо Wi-Fi залишається активним, але WebSocket-клієнт відключений або зупинений понад 30 секунд, супервізор автоматично виконує повне безпечне перезавантаження клієнта (`stop_client()` -> `start_client()`).

### 3. Очищення застарілих станів при повторному з'єднанні (Stale State Clearing)
- При відновленні з'єднання (`WEBSOCKET_EVENT_CONNECTED`) таблиця активних тривог `active_alerts_table_` та прапорці тактичних загроз очищуються перед отриманням свіжого пакету `0xA1`, що гарантує 100% відповідність реальному стану без «фантомних» або застарілих тривог.
- Буфер прийому бінарних фрагментів `rx_bin_buf_` розширено з 1024 до 4096 байт із суворим контролем переповнення, що усуває ризик пошкодження пакетів при фрагментованій передачі великих масивів тривог.

### 4. Відображення статусу зв'язку в Web UI та REST API
- У `GET /api/status` додано поле `jaam_connected` (boolean).
- У веб-інтерфейсі в секції «Повітряна тривога» додано бейдж стану зв'язку з сервером (`Сервер: онлайн` / `Сервер: офлайн`).
- Утиліта `tools/device.py` тепер відображає `JAAM WS Connected: ON/OFF` та поточний статус тривоги у виводі команди `status`.

### 5. Підвищення версій компонентів
- **ESPHome Firmware**: `v2.2.1`
- **GD32 Coprocessor Firmware**: `v1.3.2` (`0x0132`, без змін)
- **Graphic Assets Container**: 47 активних асетів (без змін)
