# HTRAM Release v2.4.1

## Огляд релізу (Release Overview)
Реліз `v2.4.1` переводить клієнт повітряних тривог на новий сервісний WebSocket API проєкту [JAAM (jaam.net.ua)](https://jaam.net.ua) (`/data_service_v1`) відповідно до оновлених правил та дедлайну 1 грудня 2026 року, виправляє відображення жовтого рівня тривоги при встановленому legacy-біті та додає однокроковий SWD-пайплайн конверсії стокових пристроїв без перепаювання.

## Основні зміни (Key Features & Improvements)

### 1. Міграція на сервісний WebSocket API JAAM (`/data_service_v1`)
- **Новий ендпоінт**: клієнт `jaam_ws` переведено з `/data_fusion_v1` (призначеного виключно для офіційних прошивок JAAM) на `/data_service_v1` (`ws://ws.jaam.net.ua:80/data_service_v1`); додано валідацію схеми із забороною застарілих шляхів прошивок та вилучено мертвий код `/data_v4` (~20 КБ додаткового вільного DRAM на ESP32).
- **Ідентифікація сервісу (`hello:<JSON>`) та постійний `client_id`**:
  - При першому старті на пристрої генерується випадковий UUID v4 (`esp_fill_random`) та зберігається в енергонезалежній пам'яті NVS (`jaam_client_id_v1`).
  - Одразу після встановлення WebSocket-з'єднання надсилається обов'язковий пакет `hello` з полями `service_id` (`htram-esphome`), `client_id`, `name`, `website`, `contact` та `version`, а також заголовок `User-Agent`.
- **Оновлений backoff та коди відмови**:
  - Експоненційна затримка перепідключення `4 → 8 → 16 → 32 → 64 → 128 с` із випадковим відхиленням `±20%`, кратним `2 с` і стелею `128 с` (`102–128 с` на максимумі); скидання затримки відбувається лише після стабільної сесії тривалістю `≥ 60 с`.
  - Обробка кодів закриття `1008`, `4403` (`service_blocked`) та `4410` (`use_service_endpoint`) з логуванням причини та миттєвим переходом до максимальної затримки (`128 с`).
  - У потоці одноразових подій `0xA2` записи з `flags = 0` ігноруються й не скидають активні сповіщення до спливання локального TTL.

### 2. Коректне збереження жовтого рівня тривоги
- Виправлено умову визначення `red_air` в `alert.yaml`, щоб одночасна наявність legacy-біта повітряної тривоги (`біт 0`) разом із жовтим рівнем (`біт 11`, наприклад `0x0801`) відображалася жовтим кольором цифр (`#FFC53D`), а не примусово червоним.

### 3. Однокрокова 5-дротова конверсія стокових пристроїв
- Утиліта `tools/convert.py` підтримує повний цикл конверсії стокового пристрою з коробки (`make convert`) через одне 5-дротове SWD-підключення Raspberry Pi Pico (`debugprobe`) без перепаювання ліній UART і без перемички `GPIO0`.

### 4. Підвищення версій компонентів
- **ESPHome Firmware**: `v2.4.1`
- **GD32 Coprocessor Firmware**: `v1.3.4` (`0x0134`)
- **Graphic Assets Container**: 52 активних асети (`21,178` байтів)
