# HTRAM Release v2.1.2

## Огляд релізу (Release Overview)
Реліз `v2.1.2` усуває проблему втрати Wi-Fi з'єднання при віддаленому оновленні через публічні релізи GitHub («1-клік оновлення»), додає автоматичне збереження активних Wi-Fi креденшалів у постійну пам'ять NVS при будь-якому підключенні та виправляє графічне накладання (ghosting) QR-коду на картку інформації точки доступу (SoftAP).

---

## Основні зміни (Key Features & Improvements)

### 1. Автоматичне збереження Wi-Fi креденшалів у NVS (Wi-Fi Persistence)
- **Проблема**: Публічні релізи з GitHub Actions компілюються з плейсхолдерами (`YourWiFi`). Якщо пристрій раніше прошивався локально або через консоль, реальні Wi-Fi креденшали були скомпільовані в бінарний код і були відсутні в NVS. Після 1-клік оновлення пристрій не знаходив збереженого Wi-Fi і переходив у режим точки доступу SoftAP `HTRAM Setup`.
- **Рішення**:
  - Реалізовано функцію `auto_save_active_wifi()`, яка при кожному успішному підключенні до мережі (`wifi.on_connect`) або при старті системи перевіряє стан NVS і записує активні SSID та пароль у постійний розділ NVS (`htram_wifi_perm_v1`), ігноруючи плейсхолдер `"YourWiFi"`.
  - Перед запуском завантаження оновлення в `trigger_ota_update` додано примусове збереження активних креденшалів у NVS.
  - Безпечне відновлення Wi-Fi з NVS на ранньому етапі завантаження без передчасного доступу до неініціалізованих структур ESPHome.

### 2. Виправлення графічного накладання на екрані SoftAP (Modal AP Ghosting Fix)
- При перемиканні між сторінкою 0 (QR-код) та сторінкою 1 (текстова картка з IP-адресою та інструкціями) об'єкти QR-коду та білої підкладки тепер явно приховуються (`lv_obj_add_flag(..., LV_OBJ_FLAG_HIDDEN)`), усуваючи промальовування тексту поверх білого квадрата QR.

### 3. Підвищення версій компонентів
- **ESPHome Firmware**: `v2.1.2`
- **GD32 Coprocessor Firmware**: `v1.3.1` (без змін)
- **Graphic Assets Container**: 47 активних асетів (без змін)
