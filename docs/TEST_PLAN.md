# HTRAM — план тестування пристрою з новою прошивкою

Документ-чекліст для сесії тестування «людина + пристрій». Складено з фактичного
коду на 2026-09-06: [`firmware/gd32/`](../firmware/gd32/) (GD32F150) та
[`esphome/htram.yaml`](../esphome/htram.yaml) + [`custom_components/htram_gd32/`](../esphome/custom_components/htram_gd32/) (ESP32).

**Як користуватись.** Кожен кейс має ID (`A1`, `B3`…) — ним і кличемо його в
розмові. Статус ставимо прямо в таблицю:

| позначка | значення |
| --- | --- |
| ⬜ | не тестовано |
| ✅ | працює як очікувалось |
| ⚠️ | працює частково / з зауваженням |
| ❌ | не працює (баг) |
| ⛔ | функції немає — тестувати нічого (див. §Прогалини) |
| ➖ | пропущено свідомо (немає умов) |

У колонку «Факт» пишемо, що саме побачили: значення, час, текст помилки. Один
рядок = один спостережуваний факт, не «ок».

---

## 0. Передумови сесії

- [ ] Записати версії, з якими тестуємо: `GD32 Firmware` (сутність у HA, формат
      `1.0.0 g<hash>[+] (дата UTC)`), `ESPHome Version`, git-хеш робочого дерева.
- [ ] Батарея заряджена > 60 % (гейт OTA — `3500 mV`).

> **Режим експлуатації: пристрій постійно під живленням.** Батарея — лише буфер
> на перенесення й на просадки мережі; навіть на заводській прошивці її не
> вистачало на добу. Тому кейси автономності (`F5`, `H11`) позначені ➖, а
> прогалину «немає захисту від глибокого розряду» знижено до 🟢. Що лишається
> важливим: заряд справді має йти (`F2`, `H8`) і перехід USB↔батарея не має
> ронити пристрій (`F4`).
- [ ] Доступ: HA з пристроєм у мережі, `esphome logs esphome/htram.yaml` в окремому
      терміналі (потік логів — головне джерело фактів), веб-інтерфейс `http://<ip>/`.
- [ ] Стенд Pico/SWD **не** підключений для більшості кейсів. Якщо підключаємо —
      строго за порядком з [BENCH.md §1.1](BENCH.md) (спершу живлення плати, потім
      USB Pico; вимкнення — у зворотному порядку).
- [ ] Мати під рукою шлях відновлення: [`tools/swd/rescue_under_reset.py`](../tools/swd/rescue_under_reset.py)
      і `flash.py --factory` — на випадок, якщо блок M (OTA) піде не так.
- [ ] Секундомір/телефон — кілька кейсів вимірюють час (30 с телеметрія, 7 с слот,
      3 с утримання, 30 с підсвітка standby).
