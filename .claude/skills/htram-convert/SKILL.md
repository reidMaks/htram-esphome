# Конверсія нового (стокового) пристрою HTRAM (`htram-convert`)

Цей скіл описує актуальний однокроковий процес перепрошивки нового («з коробки») пристрою HTRAM на кастомну прошивку (ESP32 + GD32F150 + SPI Flash асети) за допомогою одного Raspberry Pi Pico (`debugprobe`) та однієї наскрізної команди.

Повна технічна документація та вбудовані схеми: [`docs/CONVERSION.md`](../../docs/CONVERSION.md).

---

## 1. Ключова архітектура конверсії (5 дротів, без перепаювання і без `GPIO0`)

Весь цикл конверсії (`prep` → `probe` → `esp` → `dump` → `unlock` → `flash` → `verify`) виконується на **одному незмінному підключенні з 5 контактів** (паяння один раз або 5-пінова пого-пін накладка):

| Пін Pico (`debugprobe`) | Колір на схемах | Точка на платі HTRAM | Сторона плати | Призначення |
| :--- | :--- | :--- | :--- | :--- |
| **Pico GP2** (pin 4) | Синій | **`TP16`** (`PA14`, SWCLK) | Тильна (під `U5` GD32) | SWD тактування GD32 |
| **Pico GP3** (pin 5) | Зелений | **`TP17`** (`PA13`, SWDIO) | Тильна (під `U5` GD32) | SWD дані GD32 |
| **Pico GP4** (pin 6, TX) | Жовтий | **`GPIO3`** (`RXD0`, пад **34**) | Лицьова (модуль `U6` ESP32) | UART0 RX ESP32 |
| **Pico GP5** (pin 7, RX) | Помаранчевий | **`GPIO1`** (`TXD0`, пад **35**) | Лицьова (модуль `U6` ESP32) | UART0 TX ESP32 |
| **Pico GND** (pin 8) | Чорний | **`GND`** (пад **38** або екран USB) | Лицьова (модуль `U6` ESP32) | Спільна земля |

### Чому не потрібні ні `GPIO0` (пад 25), ні міжчиповий UART (`GPIO16`/`GPIO17`, пади 27/28):
1. **Автоматичний вхід ESP32 у `ROM Download Mode` (`boot:0x3`) по SWD**:
   - Коли скрипт `tools/convert.py` зупиняє ядро заводської GD32 по SWD (`target.halt()`), вимикає живлення ESP32 на 600 мс і знову піднімає `PC15=1`, `PF7=1`, `PB3=1`, утримуючи пін **`PA1 = 0` (`Output LOW`)**, ESP32 з першої спроби автоматично завантажується у **`boot:0x3 (DOWNLOAD_BOOT)` (`waiting for download`)**!
   - Замикати `GPIO0` (пад 25) пінцетом чи натискати кнопку `SW1` **не потрібно**.
2. **SWD-mailbox стаби для GD32 (`dump`, `unlock`, `flash`)**:
   - Читання 64 КБ заводської прошивки з-під `RDP1` ([`tools/swd/swd_flash_dump.c`](../../tools/swd/swd_flash_dump.c), ~5 с), зняття `RDP` ([`tools/swd/rdp_unlock.c`](../../tools/swd/rdp_unlock.c)) та запис нової прошивки GD32 ([`tools/swd/swd_flash_writer.c`](../../tools/swd/swd_flash_writer.c), ~27 с) працюють виключно через поштову скриньку в SRAM по SWD (`TP16`/`TP17`).

Візуальні схеми підключення лежать у [`docs/wiring/swd.svg`](../../docs/wiring/swd.svg) та [`docs/wiring/esp-uart0.svg`](../../docs/wiring/esp-uart0.svg) і вбудовані прямо в [`docs/CONVERSION.md`](../../docs/CONVERSION.md).

## 2. Єдина наскрізна команда

Весь процес запускається **однією командою**, яка проходить усі 7 етапів поспіль і зупиняється лише там, де потрібна дія людини:

```bash
# Для нового автономного пристрою (прошиває повний esphome/htram.yaml + асети SPI Flash):
make convert
# або напряму:
uv run python3 tools/convert.py --all --yes

# Якщо новий пристрій замінює конкретний вузол домашнього флоту (зі збереженням імені/інтеграції HA):
make convert CONFIG=esphome/htram-9436b0.yaml   # Кабінет (office)
make convert CONFIG=esphome/htram-954f48.yaml   # Спальня (bedroom)
make convert CONFIG=esphome/htram-c1da24.yaml   # Вітальня (living)
```

### Що робить команда і де саме чекає на користувача:

1. **Етап `prep` (Автоматично)**:
   - Перевіряє тулчейн (`arm-none-eabi-gcc`, `pyocd`, `esphome`), створює `esphome/secrets.yaml` із шаблону (якщо його ще немає), автоматично збирає `firmware/gd32/build/gd32_firmware.bin` і пакує `firmware/gd32/build/flash_assets.bin`.
2. **Етап `probe` (Пауза лише якщо Pico/плату ще не під'єднано)**:
   - Якщо 5 дротів כבר припаяно, плата заживлена, а Pico підключений до USB — миттєво перевіряє `CPUID` по SWD і `/dev/ttyACM*` та йде далі без зупинки.
   - Якщо ні — виводить підказку з розпіновкою та обов'язковим порядком увімкнення й чекає на `Enter`.
3. **Етап `esp` (Повністю автоматично, ~80 с)**:
   - Компілює повну прошивку ESPHome (`esphome/htram.yaml` або переданий `--config`).
   - Програмно через SWD (`PA1=0` при старті `PB3`/`PF7`) переводить ESP32 у `Download Mode` (`boot:0x3`), запалює зелені світлодіоди на платі, заливає `firmware.factory.bin` через `/dev/ttyACM0`, зчитує MAC-адресу ESP32 і прив'язує її до 96-бітного `UID` чипа GD32 у `tools/swd/factory/current-esp`.
4. **Етап `dump` (Повністю автоматично, ~5 с)**:
   - Через SWD-mailbox стаб (`swd_flash_dump.c` зі зняттям `CDBGPWRUPREQ`) вичитує всі 64 КБ заводської прошивки з-під `RDP1`, перевіряє CRC-16 та векторну таблицю і зберігає іменований бекап у `tools/swd/factory/gd32-<uid>.bin` + `.json`.
5. **Етап `unlock` → ⏸️ ЗУПИНКА №1: Скинути живлення плати один раз (POR)**:
   - Автоматично перевіряє наявність валідного дампа саме для цього `UID` і записує байти опцій `RDP=0xA5` (`0x5AA5`) через `rdp_unlock.c`.
   - **Чекає на єдину фізичну дію користувача зі стендом**:
     1. Від'єднати USB Pico від комп'ютера.
     2. Повністю знеструмити плату (від'єднати зарядку та акумулятор на 3 с).
     3. Подати живлення на плату знову (на цьому POR відбувається апаратний mass erase GD32).
     4. Під'єднати USB Pico назад у комп'ютер і натиснути `Enter`.
   - Перевіряє, що `OBSTAT == 0xFFFFFF00` (`RDP знято`).
6. **Етап `flash` (Повністю автоматично, ~27 с)**:
   - Заливає нашу прошивку `gd32_firmware.bin` через `swd_flash_writer.c` із перевіркою CRC-16, після чого скидає і запускає GD32 (`target.reset(); target.resume()`).
   - GD32 одразу піднімає рейку живлення ESP32 (`PB3=1`, `PF7=1`), і ESP32 автоматично завантажує записану на етапі `esp` прошивку!
7. **Етап `verify` → ⏸️ ЗУПИНКА №2: Налаштування Wi-Fi (лише якщо Wi-Fi ще не налаштовано) + Авто-заливка асетів**:
   - Якщо у `esphome/secrets.yaml` вже були прописані домашні `wifi_ssid`/`wifi_password`, пристрій сам підключається до Wi-Fi.
   - Якщо Wi-Fi новий (або mDNS `.local` не резолвиться на хості), скрипт зупиняється і просить:
     - підключитись телефоном/ноутбуком до точки доступу **`HTRAM Setup`** (QR-код з'являється на екрані годинника через 15 с після старту) та обрати домашню Wi-Fi мережу у вікні `http://192.168.4.1`, або
     - ввести IP-адресу пристрою в терміналі й натиснути `Enter`.
   - Щойно ESP32 відповідає по HTTP, скрипт **автоматично дочікується ініціалізації `W25Q32 4MB` SPI Flash, заливає 52 графічні асети (`flash_assets.bin`)** і виводить таблицю живої телеметрії (`CO2`, `Temperature`, `Humidity`, `Battery`, `GD32 Firmware`).

## 3. Як ШІ-агент має проводити користувача через конверсію

Коли користувач просить прошити новий пристрій HTRAM:

1. **Уточни цільову конфігурацію (якщо не вказано)**:
   - Чи це новий автономний пристрій (`esphome/htram.yaml`), чи заміна одного з пристроїв домашнього флоту (`office` → `esphome/htram-9436b0.yaml`, `bedroom` → `esphome/htram-954f48.yaml`, `living` → `esphome/htram-c1da24.yaml`)?
2. **Крок 1 — Перевір підключення 5 дротів та порядок живлення**:
   - Дай користувачу посилання на схеми в [`docs/CONVERSION.md`](../../docs/CONVERSION.md) (`GP2`→`TP16`, `GP3`→`TP17`, `GP4`→пад `34`, `GP5`→пад `35`, `GND`→пад `38`).
   - Нагадай обов'язковий порядок увімкнення: **спершу живлення плати (акумулятор або окрема USB-зарядка, НЕ цей ПК) → переконатись, що плата працює → увімкнути USB Pico в ПК**.
3. **Крок 2 — Запусти єдину команду і веди користувача через дві зупинки**:
   - Ти можеш або запропонувати користувачу виконати `make convert` у своєму терміналі, або **сам запустити команду у фоні** через `run_command`:
     ```bash
     uv run python3 tools/convert.py --all --yes
     ```
     (або з `--config esphome/htram-9436b0.yaml`).
   - Коли фонова задача дійде до **Зупинки №1 (`unlock` — перезапуск живлення POR)**:
     - Повідом користувача, що ESP32 вже прошито, заводський дамп GD32 (64 КБ) збережено, і байти опцій записані.
     - Попроси виконати **один перезапуск живлення**: `1) Від'єднати USB Pico → 2) Повністю знеструмити плату на 3 с → 3) Увімкнути живлення плати → 4) Під'єднати USB Pico` і написати «готово».
     - Коли користувач напише «готово», надішли `\n` у фонову задачу через `manage_task(Action="send_input", TaskId=..., Input="\n")`.
   - Коли фонова задача прошиє GD32 і дійде до **Зупинки №2 (`verify` — Wi-Fi / IP)**:
     - Якщо пристрій ще не знайдено автоматично, попроси користувача підключити годинник до Wi-Fi через точку доступу **`HTRAM Setup`** (QR-код на екрані пристрою) або повідомити його IP-адресу з роутера, і передай `<ip>\n` у задачу через `manage_task(Action="send_input", ...)`.
4. **Крок 3 — Фінальна перевірка та завершення**:
   - Переконайся, що `flash_assets.bin` успішно записано у SPI Flash (`[ok] Assets successfully written to SPI Flash`), а сенсори (`CO2`, `Temperature`, `Humidity`, `Battery`) віддають валідні значення.
   - Якщо пристрій замінив один із вузлів флоту (`office`, `bedroom`, `living`) і отримав новий IP, онови IP в [`tools/device.py`](../../tools/device.py), [`Makefile`](../../Makefile), [`AGENTS.md`](../../AGENTS.md) та [`tests/tools/test_device.py`](../../tests/tools/test_device.py).
   - Нагадай безпечний порядок від'єднання: **1) Від'єднати USB Pico → 2) Вимкнути живлення плати → 3) Відпаяти 5 дротів (або зняти з пого-пінів) і зібрати корпус**.
